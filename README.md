# Event Manager

Учебный REST API для создания и управления событиями на ASP.NET Core.

## Запуск

Для запуска нужен .NET SDK 10.

```powershell
dotnet run --project .\EventManager.Api\EventManager.Api.csproj
```

После запуска Swagger UI будет доступен по адресу:

```text
http://localhost:5239/swagger
```

Если порт переопределён в настройках запуска, его актуальное значение отображается в консоли приложения.

## API

Базовый путь: `/events`.

| Метод | Путь | Описание | Успешный ответ |
|---|---|---|---|
| `GET` | `/events` | Получить список событий | `200 OK` |
| `GET` | `/events/{id}` | Получить событие по идентификатору | `200 OK` |
| `POST` | `/events` | Создать событие | `201 Created` |
| `PUT` | `/events/{id}` | Полностью обновить событие | `200 OK` |
| `DELETE` | `/events/{id}` | Удалить событие | `204 No Content` |

Если событие с указанным идентификатором не найдено, `GET`, `PUT` и `DELETE` вернут `404 Not Found`.

### Фильтрация и пагинация

`GET /events` поддерживает параметры строки запроса:

| Параметр | Тип | Значение по умолчанию | Описание |
|---|---|---|---|
| `title` | `string` | — | Часть названия события без учёта регистра |
| `from` | `date-time` | — | Минимальные дата и время начала события включительно |
| `to` | `date-time` | — | Максимальные дата и время окончания события включительно |
| `page` | `integer` | `1` | Номер страницы, начиная с 1 |
| `pageSize` | `integer` | `10` | Количество событий на странице, минимум 1 |

Параметры фильтрации можно комбинировать. Например:

```http
GET /events?title=workshop&from=2026-09-01T00:00:00&to=2026-09-30T23:59:59&page=1&pageSize=10
```

Ответ содержит отфильтрованные события и данные пагинации:

```json
{
  "totalCount": 1,
  "events": [
    {
      "id": "66a1ed2f-a302-4441-a228-559f328bbe5e",
      "title": "Воркшоп по ASP.NET Core",
      "description": "Практика разработки Web API.",
      "startAt": "2026-09-19T11:00:00",
      "endAt": "2026-09-19T14:00:00"
    }
  ],
  "page": 1,
  "pageSize": 10
}
```

### Создание события

`POST /events`

```json
{
  "title": "Воркшоп по ASP.NET Core",
  "description": "Практика разработки Web API.",
  "startAt": "2026-09-19T11:00:00",
  "endAt": "2026-09-19T14:00:00"
}
```

Успешный ответ содержит созданное событие и заголовок `Location` со ссылкой на него:

```text
Location: /events/{id}
```

### Обновление события

`PUT /events/{id}`

Тело запроса имеет тот же формат, что и при создании события.

## Валидация

- `title`, `startAt` и `endAt` обязательны;
- `title` не может быть пустым или состоять только из пробелов;
- дата окончания должна быть позже даты начала.

При невалидных данных API возвращает `400 Bad Request`. Если событие не найдено, API возвращает `404 Not Found`. Ошибки сервисного слоя представлены в формате `ProblemDetails`:

```json
{
  "title": "Request processing failed",
  "status": 404,
  "detail": "Event not found."
}
```

Необработанная ошибка возвращается в том же формате со статусом `500 Internal Server Error`; внутренние детали исключения клиенту не передаются.
